## 2. 游戏与 OK-WW 界面条件

当前实机条件：

- 原生 Mac 版《鸣潮》；
- 游戏捕获帧 `1920 × 1080`；
- 画面比例 `16:9`；
- OK-WW 使用 `ScreenCaptureKit`，目标帧率 30 fps；
- 输入后端为 `MacForeground`；
- OCR 使用 ONNX CPU 路径；
- 任务执行时游戏必须在前台。

本轮实机窗口：

```text
bundle_id: com.kurogame.wutheringwaves.global
title: 鸣潮
capture resolution: 1920x1080
```

窗口 ID 和 PID 每次启动都会变化，不能写成持久配置。

## 8. macOS 输入约定

### 普通按键

通过 Quartz `CGEvent` 向当前前台游戏发送。

### 原子修饰点击

需要 `Option/Alt + 点击` 时，应在同一个后端命令中：

1. 按下修饰键；
2. 发送带修饰标志的鼠标移动、按下和抬起；
3. 释放修饰键。

不要依赖“先发一个 Alt，再单独点击”的松散组合。

### 无坐标鼠标动作

自动战斗的普通攻击可能没有显式坐标。当前处理：

1. 使用当前 Quartz 光标位置；
2. 无法读取时使用游戏窗口中心；
3. 抬起事件沿用最近一次有效坐标。

### 前台保护

游戏不在前台时，macOS 输入后端应拒绝发送输入，防止误操作 ChatGPT、终端或其他
应用。

## 9. 更换分辨率或 UI 后的复校顺序

1. 确认捕获到的真实帧尺寸。
2. 确认索拉指南标题 OCR 框。
3. 校准索拉指南、活跃行迹、素材获取三个侧栏入口。
4. 校准素材获取左侧 6 个大类卡片。
5. 校准右侧副本名称、按钮和纵向滚动条。
6. 校准活跃行迹的 `N/180` OCR 区域和同行按钮。
7. 校准大世界队伍 UI 与 F 提示。
8. 先做只读截图验证，再测试无害页面切换。
9. 最后才测试传送、领取或战斗。

每次坐标校准都必须保存：

- 分辨率；
- 页面标题；
- 相对坐标；
- 对应截图；
- 实际点击结果；
- 是否需要 `Option/Alt`；
- 代码与配置是否已经重启加载。
